Install on Windows

  1. Download {{dl:windows-x64-Setup:file}} ({{dl:windows-x64-Setup:size}}).
  2. Double-click it and choose Install. A.S.T.R.O AI installs just for your user account, so there's no administrator prompt.
  3. Launch it from the Start menu or the desktop shortcut. The app is called A.S.T.R.O AI Clean.
"Windows protected your PC"? The installer isn't code-signed yet, so SmartScreen warns about it. Click More info → Run anyway. To make sure the file is genuine, check its SHA-256 checksum first.

Rather not install anything? Download the portable zip, extract it anywhere, and run AstroAI-Clean.exe.

A.S.T.R.O AI uses the Microsoft Edge WebView2 runtime. It's built into Windows 11 and up-to-date Windows 10. If it's missing, the app tells you and opens Microsoft's download page.

Install on Linux

On Debian, Ubuntu and their derivatives, install the package with apt so it pulls in dependencies (WebKitGTK 4.1, libcurl, OpenSSL 3):

sudo apt install ./{{dl:_amd64:file}}

Then open A.S.T.R.O AI Clean from your app menu, or run astro-ai-clean in a terminal.

On other distributions, use the portable tarball:

tar xzf {{dl:linux-x64-portable:file}}
cd astro-ai-clean-{{version}}-linux-x64-CLEAN
./install.sh        # optional: adds it to your app menu (no root needed)
./astro-desktop

Requirements: 64-bit, glibc 2.35 or newer (Ubuntu 22.04+, Debian 12+, Fedora 36+), and WebKitGTK 4.1 (libwebkit2gtk-4.1-0, or webkit2gtk4.1 on Fedora).

Install on macOS

Download the disk image ({{dl:macos-universal:file}}). It's one universal app that runs natively on Apple Silicon and Intel. Open it and drag A.S.T.R.O AI Clean into Applications.

The app isn't notarized by Apple yet, so the first time you open it, macOS says it can't check the app. Right-click (or Control-click) A.S.T.R.O AI Clean in Applications and choose Open, then Open again. On newer macOS versions, go to System Settings › Privacy & Security and click Open Anyway. You only do this once.

Or build it yourself

If you'd rather compile it on your own Mac, use the build kit. It takes about a minute, and macOS opens an app you built yourself without the warning.

  1. Install Apple's free command line tools (skip this if you already have Xcode): 
    xcode-select --install
  2. Download and unpack the build kit, then run the build script: 
    tar xzf {{dl:macos-source:file}}
cd AstroAI-{{version}}-macos-source-CLEAN
./build_mac.sh
  3. Open the .dmg it creates and drag A.S.T.R.O AI Clean into Applications.

Needs macOS 11 Big Sur or newer. To build for just one architecture, use ARCHS="-arch arm64" ./build_mac.sh. Because you built the app yourself, macOS opens it without the warning it shows for downloaded apps.

Your first chat

Open A.S.T.R.O AI and type a question in the box that says Ask A.S.T.R.O AI. That's it: there's no account and nothing to set up. The model menu above the chat starts on One Brain · all 26 minds together, and the status bar at the bottom left shows how many models are ready.

Under the message box you'll find:

  • General / Compare / Web: the answer mode. Web brings in fresh search results.
  • Auto: the response language. Set it to answer in a specific language.
  • Microphone to dictate, and the wave button for a live voice conversation.
  • + to attach files.

One Brain & single models

With One Brain selected, every available model works on your question together, in four stages shown on the progress card:

StageWhat happens
PlanThe team reads your question and context, then agrees on an approach.
WorkEach model drafts its own answer at the same time.
ReviewThe drafts are compared, disagreements are resolved, and facts and code are checked.
AnswerOne model merges the best parts into a single reply.

Under each answer you'll see how many models contributed, which model merged it, how long it took and how confident the team was.

It takes a while, on purpose. Waiting for slow models is part of the deal: a full answer usually takes a few minutes. Press Answer now on the progress card to stop waiting and write the answer from what's ready. For quick back-and-forth, pick a single model from the model menu instead.

Free tiers have rate and daily limits, and providers can change them at any time. When one runs out, the rest of the team keeps answering. Limits reset on the provider's schedule, usually daily.

Adding free keys

The quickest way: open Settings → Providers and use the Get more free models card at the top (or type /free-keys in chat). For Groq, OpenRouter, Mistral and Cohere it opens the sign-up page, you paste the key, and A.S.T.R.O AI tests it straight away and shows how many models it added. It takes about a minute each. Free tiers have daily limits set by each provider; more keys give you more room, not unlimited use.

Out of the box, A.S.T.R.O AI uses providers that need no key. To grow the team, create free API keys with your own accounts and paste them into Settings → Providers & keys. New models join One Brain straight away.

A.S.T.R.O API key

If you saved provider keys in your A.S.T.R.O account, you don't need to paste them into every computer. Create an A.S.T.R.O key in Account → API keys (it starts with astro_sk_) and paste it into the A.S.T.R.O API key card at the top of Settings → Providers & keys, then press Test.

  • A.S.T.R.O auto answers through your saved free providers and fails over between them.
  • A.S.T.R.O API: pick any model lists every model your account can reach, for manual picking.
  • Paid providers are used only if you turn them on for your account. The limit is 5,000 requests a day per account.

Workspace

The Workspace is a code editor with an AI engineering team built in. Pick a project in the top-left menu (a starter my-project is included). Then:

  • Edit files in tabs, with find and replace, folding and word wrap.
  • Run the current file with Ctrl + Enter. Output, errors and the exit code appear below. HTML files open in the live Preview.
  • Open the Terminal tab for a real shell in your project folder.
  • Ask the team (right panel) to build, fix or explain something. Use Team for the best results, Fast for speed, or Agent to let it work on its own. Turn on Plan for multi-step goals and Auto-fix to retry failed runs.
  • Every change is saved as a version first. Use the history button in the file panel to compare versions or undo.
  • Open the project menu and choose Open folder… to work on any folder on your computer (see Folders, skills, MCP & plugins).
  • The Problems tab lists errors and warnings and underlines them in the editor. Press Ctrl + K and choose Turn on AI inline suggestions for grey ghost text (press Tab to accept), and select code and press Ctrl + I to edit it with AI.

Running code uses the tools installed on your computer: Node.js for JavaScript, Python, a C/C++ compiler (gcc or clang), and a JDK for Java. HTML and CSS need nothing extra. On Windows, the terminal works best with Git for Windows installed, because it provides bash.

Agent

Open Agent in the sidebar, choose a project, and describe the job, for example "build a to-do app with an Express API, start it and test it with curl". The team of models plans the work and reviews it, and a fast model carries out the steps. The agent can:

  • run commands and start servers,
  • create, edit and delete files,
  • search the web,
  • check its results and fix its own errors until the job is done.

Choose a permission mode with the chip under the message box, or type /mode:

  • Plan: read-only. The agent inspects the project and writes a plan; press Run this plan to carry it out.
  • Ask: you approve every file change and command with Allow, Allow all in this run or Deny. Folders you open start in this mode.
  • Auto: the agent works on its own.

Type / for commands: /init writes an AGENTS.md, and there are also /plan, /review, /test, /commit, /compact, /skills, /mcp and /agents. The icon rail on the right switches the side panel between Session, Changes (with a diff per file), Files, Terminal and Preview. A checkpoint is taken before each job, so you can roll back.

Your runs are listed on the left with their status, time, files changed and mode. Each finished run ends with a Recap line: how many files changed and whether the tests passed, still fail or weren't run. The Session panel shows:

  • Context: roughly how much of the model's context the conversation uses, and the cost (free models cost $0.00),
  • Project: the git branch, uncommitted files, the mode, and the checkpoint with Undo all,
  • Context sources: the rules files and skills the agent was given,
  • MCP servers: switch each trusted server on or off for the agent (untrusted servers ask first),
  • Usage and Turn stats: steps, actions, files and time.

Risky commands

Even in Auto mode, the agent stops and asks before commands that are hard to undo: sudo/su, piping a download into a shell (curl … | sh), deleting your home folder, a drive root or everything with *, force-pushing with git, formatting or overwriting disks (mkfs, dd, diskpart), del /s, recursive chmod on /, shutting down, deleting Windows registry keys and publishing packages. You can Allow it once, Allow all in this run or Deny. When nobody can answer (for example astro -p in a script), the command is blocked and the agent is told why. Everyday clean-ups such as rm -rf node_modules dist are not affected. To turn the check off, start A.S.T.R.O AI with ASTRO_ALLOW_RISKY=1.

Use it with care. The agent runs real commands on your computer. Give it a project folder you're happy for it to change, and keep backups of anything that matters.

Terminal & parallel agents

Terminal only: install astro without the desktop app or setup wizard with curl -fsSL https://esoexe.github.io/astro-ai/install.sh | sh on Linux and macOS, or irm https://esoexe.github.io/astro-ai/install.ps1 | iex in PowerShell on Windows. It installs to your user folder, verifies the download's SHA-256 and adds astro to your PATH. On the first run it starts its local engine by itself and works right away with the free models that need no key. To add more providers, open http://127.0.0.1:47612 in your browser while it runs.

The desktop downloads include astro, the A.S.T.R.O AI agent for your terminal. It is /usr/bin/astro with the Linux .deb. On Windows, Setup adds it to your PATH, so open a new terminal after installing. On macOS it is inside the app, and the installer prints the one-line link command. If the app is closed, astro uses the app's engine and starts it when needed.

  • cd my-project && astro opens the full-screen terminal app on that folder: a conversation view, a status line and a side panel with the mode, model, changed files and to-do list. Type / for the 23 commands, press Ctrl+C to stop the agent and use /undo to put the folder back. astro --classic (or ASTRO_TUI=0) keeps the plain line-by-line view.
  • astro -p "fix the failing test" runs once for scripts and CI. Add --json for one JSON event per line, and --plan, --ask or --auto to choose the mode.
  • astro parallel "add dark mode" "write tests" --merge runs several agents at once, each in an isolated copy of the project: a git worktree in a repository, or a copy otherwise. Your files are not touched until you merge.
  • astro agents, astro diff <id>, astro merge <id>, astro discard <id> and astro undo <id> review and apply the work. If a file was also changed in the project after the agent started, merge combines both versions when the changes are in different places. If they overlap, it stops: use --partial to merge everything else, or --force to apply the agent's version anyway. When an agent's last test or build still fails, parallel --merge skips it so you can look first.

In the app, the Parallel chip on the Agent page does the same: one task per line, follow each agent live, answer its questions, look at the diff and merge. These agents run in the engine, so they keep working when you close the window. The Clean downloads also include a VS Code extension (.vsix) with the same commands. A project can give the agent its own tools with JSON files in .astro/tools/. The full reference, including the HTTP API, is in docs/cli.md.

Folders, skills, MCP & plugins

A.S.T.R.O AI works with the setup files that other coding tools already use, so an existing project behaves the way it does in OpenCode, Claude Code, Codex, Cursor or VS Code.

  • Open folder. In the Workspace or Agent project menu, choose Open folder…, browse to a folder and open it. The files stay where they are. Close folder only removes it from the list.
  • Rules. AGENTS.md, CLAUDE.md, GEMINI.md, .cursorrules, .cursor/rules and .github/copilot-instructions.md are given to the agent.
  • Skills. Folders with a SKILL.md in .claude/skills, .opencode/skill, .agents/skills or your global Extensions folder. The agent loads a skill when it needs one, or you can run it as /skill-name.
  • Commands and subagents. Markdown files in .claude/commands or .opencode/command become slash commands ( is replaced with what you type after the command). Files in .claude/agents become subagents.
  • MCP servers. Open Extensions → MCP to add a server, browse the official registry, or edit mcp.json. Astro also reads a project's .mcp.json, .cursor/mcp.json, .vscode/mcp.json and opencode.json. Project servers run commands on your computer, so they start only after you press Trust and start.
  • Plugins. Extensions → Plugins installs Claude Code plugins and marketplaces from a GitHub address. A plugin can add skills, commands, agents, hooks, MCP servers, themes and snippets.
  • Themes and snippets. Extensions → Themes and Snippets search Open VSX and install VS Code colour themes and snippet packs.
  • Hooks. Hooks from .claude/settings.json run your scripts before or after the agent's tools. Project hooks run only after you trust them.
  • Coding CLIs. If Claude Code, Codex, OpenCode, Gemini CLI or DeepSeek Harness is installed, the agent can hand sub-tasks to it.

Before a plugin is installed, A.S.T.R.O AI lists what it can do: runs commands automatically (hooks), starts programs (MCP servers), contains script files, adds commands, agents or skills, or is text and settings only. Nothing is written until you press Install. Themes and snippet packs from Open VSX are data only and never run code.

Only trust what you know. MCP servers, hooks and plugins can run programs on your computer. Install them from sources you trust.

Themes, tools & VS Code extensions

Themes

Open Settings › Appearance, or press Ctrl+K and type "Color theme", to pick one of 19 built-in themes. To use a VS Code theme, open Extensions › Themes, search Open VSX and click Install; it recolours the whole app, not only the editor. In the terminal app, type /theme.

Tools: compilers and language servers

Extensions › Tools lists what each language needs and what is already on your computer. Install downloads the official build into A.S.T.R.O's own tools folder: no admin rights, nothing changed system-wide, and every download is checked against the SHA-256 checksum its publisher lists. A.S.T.R.O recommends tools for the files in your project. Once a language server is installed, the editor shows completion, hover docs and live errors. F12 goes to a definition, Shift+Alt+F formats and F2 renames.

For C and C++, install clangd, plus a compiler if you don't have one (on Windows A.S.T.R.O offers a portable LLVM-MinGW). Microsoft's C/C++ extension can only be used in Microsoft's own VS Code, so A.S.T.R.O uses clangd instead. From a terminal: astro tools list, astro tools install clangd cmake ninja.

VS Code extensions (preview)

Extensions › VS Code searches Open VSX and installs desktop VS Code extensions. They need Node.js, which you can install in the Tools tab. Their commands appear in the command palette, and their messages, quick picks, status-bar items, output, problems, completion, hover and formatting show up in the app. Webviews, debuggers, tree views and extensions that start their own language client may not work yet. From a terminal: astro ext install publisher.name.

Voice

Click the microphone to dictate a message, or the highlighted Live wave button for a spoken back-and-forth conversation. The speaker button under any answer reads it aloud. Voice uses your operating system's speech engine, so the available voices and languages depend on your system. The first time, allow microphone access when asked.

Updates

A.S.T.R.O AI checks for a new version when it starts and then at most every 6 hours. Only the public version file is downloaded; nothing about you is sent. When an update is out, a banner shows what's new:

  • Update now downloads the installer from the official site and checks its SHA-256 checksum. On Windows it installs quietly and reopens the app. On macOS it opens the disk image, and on Linux the package, for you to finish.
  • Later hides the banner for this version. Settings → General → Check now checks straight away.
  • Terminal installs: astro update installs the newest version, and astro update --check only tells you if there is one. A copy of astro that came with the desktop app is updated by the app.

Languages

Every screen, setting and menu is available in English, French and Arabic (right-to-left), and the update banner shows the release notes in your language. A.S.T.R.O AI picks your system language the first time; change it in Settings → General → Interface language. Code, file names, chat messages and anything you type are never translated. The language of answers is a separate setting, Response language. A few rarely used screens are still in English.

Where your data lives

Chats, notes, tasks, projects, settings and keys are stored locally, in a per-user folder:

SystemData folder
Windows%APPDATA%\Astro AI Clean
Linux~/.local/share/astro-ai-clean (or $XDG_DATA_HOME/astro-ai-clean)
macOS~/Library/Application Support/Astro AI Clean

Logs are in the logs subfolder. To back up everything, copy this folder. To start fresh, quit the app and delete it.

Silent install (IT)

The Windows installer supports unattended installs:

{{dl:windows-x64-Setup:file}} /S [/D=C:\path\to\folder] [--no-desktop-shortcut]

By default it installs to %LOCALAPPDATA%\Programs\Astro AI Clean, for the current user. To remove it silently (add --purge to delete the user's data as well):

"%LOCALAPPDATA%\Programs\Astro AI Clean\Uninstall.exe" /S [--purge]

Package managers

Windows (Scoop), installs the portable app and the astro command:

scoop bucket add astro-ai https://github.com/esoexe/astro-ai

macOS (Homebrew), installs the app and the astro command:

brew install --cask esoexe/tap/astro-ai

Update with scoop update astro-ai or brew upgrade astro-ai.

Coding benchmark

We test the agent with a small set of 12 everyday coding tasks: fix an off-by-one bug, add a function, repair async code, make failing tests pass, rename across files, add a CLI flag, edit package.json, build an HTML form, fix a C bug, write a Makefile, write a shell script and debug from an error message. Each task starts in a fresh folder. A hidden check, which the agent never sees, runs after it finishes and decides pass or fail. The tasks, checks and runner are in the repository under bench/, so you can run them yourself with node bench/run.js.

Troubleshooting

The window doesn't open on Windows

Install the Microsoft Edge WebView2 Runtime (the "Evergreen" version), then start A.S.T.R.O AI again.

The app doesn't start on Linux

Check that WebKitGTK 4.1 is installed (sudo apt install libwebkit2gtk-4.1-0), and run astro-ai-clean from a terminal to see any error. If you see a blank window in a virtual machine, try WEBKIT_DISABLE_DMABUF_RENDERER=1 astro-ai-clean.

"Port in use" or the app can't reach its engine

A.S.T.R.O AI runs a small local engine on 127.0.0.1, starting at port 47612. It only listens on your own computer. If a firewall asks, allow local connections. If another program uses that port, close it and restart A.S.T.R.O AI.

Answers are slow or a model fails

One Brain is slow by design (see above). If a single model fails, it has probably hit a free-tier limit. Try another model, wait for the limit to reset, or add more free keys.

Code won't run in the Workspace

Install the language's tools (Node.js, Python, gcc/clang, a JDK) and make sure they're on your PATH, then restart A.S.T.R.O AI.

A model keeps failing with "not found"

Providers sometimes remove or rename models. A.S.T.R.O AI notices this and skips that model for 24 hours (it checks again later), so the rest of the team carries on. You don't need to do anything.

"Access denied" when reinstalling from the terminal on Windows

Run the install command again: the installer now closes A.S.T.R.O AI first. If it still fails, close all A.S.T.R.O AI windows, or run Stop-Process -Name astro,astro-server, and try again.

Still stuck?

Look at logs/server.log in your data folder. It usually says exactly what went wrong. Then use Settings → General → Report a problem (or astro bug in the terminal). It opens a GitHub issue form filled in with your version and recent errors, with keys, email addresses and your user name removed. You can read and edit it before sending; nothing is sent automatically. For questions, ask in Discussions.

Uninstall

  • Windows: Settings → Apps → A.S.T.R.O AI Clean → Uninstall, or use the Start menu shortcut. You can choose to remove your data too.
  • Linux (.deb): sudo apt remove astro-ai-clean. Your data in ~/.local/share/astro-ai-clean is kept. Delete that folder if you want it gone.
  • Linux (tarball): delete the folder, plus ~/.local/share/applications/astro-ai-clean.desktop if you ran install.sh.
  • macOS: drag the app from Applications to the Trash, and delete the data folder if you like.
